🎯 Problem Statement

  • Inconsistent response quality

Solution Opportunity

Goal: Build an AI-powered chatbot that handles common e-commerce queries instantly and escalates complex issues to human agents.

🎓 Project Objectives

The chatbot must:

  • Understand natural language - Process customer queries in conversational English
  • Handle core e-commerce tasks - Orders, returns, refunds, payments, products
  • Use RAG architecture - Retrieve relevant knowledge and generate contextual answers
  • Provide accurate responses - Use mock backend tools for transactional operations
  • Maintain context - Remember conversation history within session
  • Escalate intelligently - Identify critical issues and route to human support

🏗️ System Architecture

Three-Layer Architecture:

1️⃣ Frontend Layer (Presentation)

HTML5/CSS3/JavaScript chat widget with real-time messaging, quick-action buttons, and user-friendly interface

2️⃣ Backend Layer (Application)

Flask REST API that handles HTTP requests, CORS, session management, and routes queries to the AI layer

3️⃣ AI & Data Layer (Intelligence)

LLM (FLAN-T5), RAG pipeline (embeddings + FAISS), agent router (intent classification), and mock tools (order, payment, refund)

🧭 Intent Classification & Routing

How queries are processed:

1. Intent Detection

Keyword pattern matching to classify query intent (greeting, order tracking, payment, refund, FAQ, escalation)

2. Entity Extraction

Extract Order IDs, product names, issues from user text for accurate processing

3. Tool Selection & Execution

Route to appropriate tool: mock_tools (orders, payments) OR RAG QA chain (FAQs, policies)

4. Response Generation

Tool result + conversation context → FLAN-T5 generates natural, coherent response

📚 RAG (Retrieval-Augmented Generation) Pipeline

How the system answers FAQ & Policy questions:

  1. Knowledge Base (50+ documents) - FAQs, policies, shipping info, product details
  2. Embedding Generation - Documents & queries converted to vectors using Sentence-BERT
  3. Vector Search (FAISS) - Find top-5 most relevant documents for user query
  4. Context Building - Combine retrieved documents + query + conversation history
  5. LLM Generation - FLAN-T5 synthesizes final answer from context + system prompt
  6. Response Delivery - Natural, contextual answer sent back to user via API

✨ Result: Accurate answers grounded in company knowledge, not hallucinations!

Complete Data Flow

1. User Input → Chat widget sends query via AJAX to /chat endpoint

2. Backend Processing → Flask receives JSON, validates input, calls agent router

3. Intent Analysis → Classify query type (order, payment, RAG, escalation)

4a. Tool Path → If order/payment: extract order ID → call mock_tools → get result

4b. RAG Path → If FAQ: query → embeddings → FAISS search → retrieve top-5 docs → FLAN-T5 + context → generate answer

5. Memory Update → Store query & response in ConversationBufferMemory

6. Response Delivery → Return JSON with bot response to frontend

7. UI Update → Chat widget appends message bubble, displays typing indicator, handles feedback

⚠️ Current Limitations

Limitations

  • Uses mock data (no real DB)
  • English-only responses
  • Keyword-based intent (not ML classifier)
  • In-memory storage (not persistent)
  • CPU-only deployment
  • Single session context

Why It Works

  • Perfect for demonstration & testing
  • Easy to replace mock with real APIs
  • Keyword patterns are effective for e-commerce
  • Fine for local development
  • Shows end-to-end architecture
  • Scalable design (no fundamental issues)
